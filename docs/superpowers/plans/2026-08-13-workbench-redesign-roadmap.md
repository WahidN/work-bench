# Workbench Redesign Roadmap

> **For agentic workers:** This is a roadmap, not an executable plan. Each phase listed below gets its own full bite-sized plan doc (following `superpowers:writing-plans`) written just before that phase starts. Do not attempt to execute a phase from this doc alone.

**Goal:** Port the Nocturne-token, multi-screen redesign in `~/Downloads/design_handoff_workbench` (README.md + `Workbench.dc.html` + `_ds/.../styles.css`) into the existing SwiftUI Workbench app, one independently-shippable phase at a time.

**Architecture:** Eight sequential phases, each producing working, testable software. Screens not yet migrated keep their current look and behavior until their phase lands — no big-bang rewrite. Later phases depend on concrete decisions (component names, state shapes) made while implementing earlier ones, which is why only Phase 1 is fully detailed right now.

**Tech Stack:** SwiftUI (existing macOS app, `app/Workbench`), Node/TS + SQLite engine (existing, `engine/`), new: Inter font assets bundled into the app.

## Source of truth

The design handoff lives outside this repo at `~/Downloads/design_handoff_workbench/`:
- `README.md` — prose spec, screen-by-screen, with exact tokens/measurements.
- `Workbench.dc.html` — the actual markup + a JS "logic class" (`Component extends DCLogic`) showing exact state shape and behavior (pinning, palette matching, chat threading, keyboard shortcuts). Read this when the README is ambiguous.
- `_ds/nocturne-.../styles.css` — the token sheet (colors, spacing, radius, shadows) and shared component classes (`.btn`, `.tag`, `.card`, `.table`, `.input`).

This is a **design reference**, not code to port — its own runtime (`support.js`) is explicitly not to be reused. Each phase plan quotes the exact values/behavior it needs inline, so an implementer never has to go re-read the handoff folder.

## Decisions locked in (resolved 2026-08-13, do not re-litigate mid-phase)

1. **Diff view + Merge button**: fold into the global agent chat panel (Phase 3) — when the panel is scoped to a PR, it shows the diff and a Merge button alongside the thread. Not a separate detail screen, not dropped.
2. **Filter pills** (PRs: Assigned to me / Needs review / Mine; Issues: Assigned to me / Reported by me / Blocked): get real filtering logic in Phase 6, not the prototype's visual-only behavior.
3. **Project create/edit form**: kept, restyled to the new tokens in Phase 5, reachable via a "+" affordance the mockup doesn't show.
4. **Scope**: phased plans (this doc + one plan per phase below), not one giant plan.

## Global constraints

- Every phase's Swift changes must pass `xcodebuild test -scheme Workbench -destination 'platform=macOS'` run from `app/`; engine changes must pass `pnpm test` run from `engine/`.
- Swift Testing free `@Test func` tests in this codebase are NOT grouped under a suite matching the file name — `-only-testing:WorkbenchTests/<FileName>` silently matches zero tests and reports false success. Use `-only-testing:WorkbenchTests` (whole target) or the per-function form `-only-testing:'WorkbenchTests/testFunctionName()'` instead.
- `Ticket` (Swift model) / `tickets` (DB table) = "Issues" in the new UI vocabulary. Don't rename the underlying type or table — only user-facing labels/icons change — unless a phase's own plan says otherwise for a concrete reason.
- The existing spec `docs/superpowers/specs/2026-08-11-workbench-design.md`'s "Visual design" section (three-pane list+detail layout) is **superseded** by this redesign for Today/Projects/PRs/Issues. Its Goals/Architecture/Data model/Components sections still stand.
- Known pre-existing test flakiness, unrelated to this redesign: `APIClientCoreTests`, `APIClientTicketsTests`, `APIClientPRsTests`, `APIClientTodosTests`, `APIClientTodayProjectsTests` intermittently cross-contaminate under Swift Testing's default parallel execution (shared mock response state) — one observed run hung 20+ minutes on `diffOnAMergedPrSurfacesTheSpecificConflict()` before recovering. If a phase's test run shows failures in exactly these suites with mismatched-error-type symptoms (e.g. "expected conflict(...) but got decodingFailed(keyNotFound ...)"), rerun just the suite you touched in isolation before assuming your change broke it.
- Don't delete the current flat `Theme` tokens (`Theme.background`, `Theme.accent`, etc.) until Phase 8 — screens not yet migrated still use them.
- `app/Workbench.xcodeproj/` is generated by XcodeGen from `app/project.yml` and is gitignored — it is NOT part of any commit, and must not be. `project.yml` uses directory globs (`sources: [Workbench]`, `sources: [WorkbenchTests]`), so new `.swift` files are auto-discovered on the next `xcodegen generate`; no manual project wiring is ever needed when adding a file. Verified empirically 2026-08-13 by deleting the whole `.xcodeproj` and regenerating from `project.yml` alone — all tests still built and passed. Reviewers: absence of a `project.pbxproj` diff when new source files are added is CORRECT, not a missing-wiring defect.

## Phases

1. **Design tokens** — `app/Workbench/Views/Theme.swift` + bundled Inter font. Adds the full neutral/accent color ramps, spacing scale, radius scale, and heading/body font helpers alongside the existing flat tokens. No screen changes yet. **→ fully detailed in `2026-08-13-workbench-redesign-01-tokens.md`.**

2. **App shell & navigation** — `ContentView.swift`. Sidebar redesign (brand row, search/palette-launcher button stub, nav rows with counts in Today/Projects/PRs/Issues order, embedded scrollable project list, footer avatar), persistent header (kicker + heading + Agent button stub). Screens underneath keep rendering as they do today.

3. **Global agent chat panel** — new `Views/AgentChatPanel.swift` + `ViewModels/AgentChatViewModel.swift`. Engine: new `project_messages` table + `POST/GET /projects/{id}/messages`, analogous to existing ticket/PR messages. Migrates `TicketsScreen` and `PRsScreen` off their inline chat onto this shared panel (opened via the header's Agent button from Phase 2). PR scope includes the diff view + Merge button per decision #1.

4. **Today dashboard** — `Views/TodayScreen.swift`, `ViewModels/TodayViewModel.swift`. `Todo` model gains `priority` (High/Med/Low), `estimate`, `tag`, and overdue/today grouping by due date. New pinning: engine gets a `pinned` flag on `tickets`/`prs` + toggle endpoints; UI gets pinned-item-as-pseudo-task rendering and the right-rail PR/Issues preview cards (top 3 each, pin + chat-panel-open buttons).

5. **Projects** — `Views/ProjectsScreen.swift` split into a card grid (dot, name, status tag, blurb, footer stats) + project detail (Tasks/Notes tabs, facts card, "Open work" list). `Project` model gains `status` (Active/Paused/Planning), `blurb`, and `notes` (autosaved, keyed by project id). Existing create/edit form kept per decision #3, restyled, moved behind a "+" button.

6. **PR/Issues shared list** — new shared table-based list view replacing the current per-screen master-detail lists, with real filter pills (decision #2) and diff/merge folded into the Phase 3 panel (decision #1) instead of an inline detail pane.

7. **Command palette** — new `Views/CommandPalette.swift`. Global ⌘K, Esc-to-close, Enter-to-add-task-and-navigate, navigation commands (⌘1/⌘2/⌘3/⌘J), project search, add-task-from-query.

8. **Cleanup** — once every screen has migrated, remove the now-unused flat `Theme` tokens and any leftover inline-chat code paths.
